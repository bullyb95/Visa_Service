# Visa Service: как собрать и запустить (issue #18: Infrastructure + Presentation)

## Структура (как в AuctionTraidingMicroservice, ветка GD-236)

```
VisaService/
  Domain/
    VisaService.ValueObjects
    VisaService.Domain
    VisaService.Domain.Repositories.Abstractions   <- интерфейсы репозиториев (отдельный проект, как у преподавателя)
  Application/
    VisaService.Application.Models                 <- record-модели
    VisaService.Application.Services               <- use cases + AutoMapper ApplicationProfile
  Infrastructure/
    VisaService.Infrastructure.EntityFramework     <- DbContext, Configurations (Fluent API), Migrations
    Repositories.Implementations                   <- EfRepository, EfApplicantRepository, ...
  Presentation/
    VisaService.WebHost                            <- Controllers, Requests, Responses, Validators,
                                                      Mapping, Middlewares, Helpers, Program.cs
DomainApp/                                         <- консольная демонстрация Domain (не трогал)
```

## Шаги

1. Из старого репозитория удали мусор: `Properties/` (в корне), `VisaService.WebHost/`,
   `VisaService.Infrastructure.EntityFramework/` (в корне), файлы `ApplicantConfiguration.cs`,
   `OfficerConfiguration.cs` и `VisaService.Infrastructure.EntityFramework.csproj` в корне,
   а также старую папку `VisaServise/`. Потом скопируй содержимое этого архива поверх репозитория.

2. Если `dotnet ef` ещё не установлен:
   ```
   dotnet tool install --global dotnet-ef
   ```

3. Сборка:
   ```
   dotnet build VisaService.slnx
   ```

4. Новая миграция (добавились колонки email/phone, is_visa_issued, уникальный индекс по number,
   колонка Number переименована в number):
   ```
   dotnet ef migrations add AddContactInfoAndVisaDecision --project VisaService/Infrastructure/VisaService.Infrastructure.EntityFramework --startup-project VisaService/Presentation/VisaService.WebHost
   ```

5. Проверь строку подключения в `VisaService/Presentation/VisaService.WebHost/appsettings.Development.json`
   (порт 5432, БД VisaService, пароль 12345). Её можно задать и переменной окружения:
   `ConnectionStrings__ApplicationDbContext=...`

6. Запуск (миграции применяются автоматически при старте, через MigrationManager):
   ```
   dotnet run --project VisaService/Presentation/VisaService.WebHost --launch-profile http
   ```
   Swagger: http://localhost:5233/swagger. Проверка БД: http://localhost:5233/health.
   Готовый сценарий запросов лежит в `VisaService.WebHost.http`.

## Эндпоинты

| Метод | URL | Что делает |
|---|---|---|
| GET/POST | /api/v1/Applicants | список / регистрация заявителя |
| GET/DELETE | /api/v1/Applicants/{id} | заявитель с заявками / удаление |
| GET | /api/v1/Applicants/by-last-name/{lastName} | поиск по фамилии |
| GET | /api/v1/Applicants/{id}/applications | заявки заявителя |
| GET/POST | /api/v1/Officers | список / добавление офицера |
| GET/DELETE | /api/v1/Officers/{id} | офицер / удаление |
| GET | /api/v1/Officers/{id}/applications | заявки офицера |
| GET/POST | /api/v1/VisaApplications | список / создать заявку |
| GET | /api/v1/VisaApplications/{id} | заявка |
| POST | /api/v1/VisaApplications/fill-form | заявитель: заполнить анкету |
| POST | /api/v1/VisaApplications/submit-documents | заявитель: подать документы |
| GET | /api/v1/VisaApplications/{id}/result?applicantId= | заявитель: результат |
| DELETE | /api/v1/VisaApplications/{id}?applicantId= | заявитель: удалить заявку |
| POST | /api/v1/VisaApplications/accept, verify, issue, reject | офицер: принять / проверить / выдать / отказать |

Ошибки: 400 — невалидный запрос (FluentValidation или Value Object), 404 — не найдено,
409 — нарушено бизнес-правило (например, выдать визу до проверки документов).
Формат ошибок 400/409 из домена: `{ status, error, message, traceId }`.
